# v0.1 to v0.2 Transition Contract

## Purpose

This document identifies what v0.2 inherits from v0.1, what must be hardened first, and what remains deliberately deferred. It prevents the next product line from silently changing contracts.

## Inherited as stable

Unless a v0.2 requirement explicitly says otherwise, preserve:

- `deprail doctor`, `deprail discover [path]`, and `deprail scan [path]`.
- Exit code meanings, including `2` for configuration/argument errors and `3` for scanner failure or incomplete result.
- Complete, partial, and failed completeness semantics.
- Repository-relative slash-separated paths.
- Read-only, offline discovery.
- Argument-array subprocess execution and bounded process I/O.
- Canonical-root containment and symlink escape rejection.
- Content-addressed raw artifact retention.
- PURL-first identity, alias handling, severity/fixed-version provenance, and deterministic ordering.
- Terminal/machine-output separation.
- Linux/macOS/Windows verification expectations.

## Required v0.2 hardening

| Area | v0.1 observation | v0.2 action | Compatibility |
| --- | --- | --- | --- |
| JSON collections | Empty values can serialize as `null`. | Initialize empty collections and update schema examples. | Machine-output clarification; arrays are the required form. |
| CLI arguments | Extra doctor arguments were ignored. | Reject unexpected arguments before execution. | Invalid invocations become explicit configuration errors. |
| OSV contract | v2 behavior was learned during implementation. | Check in real v2 fixtures and exit-code matrix. | Supports the documented v2 range. |
| Scan root | Caller working directory once controlled scanner scope. | Add outside-root end-to-end regression coverage. | Correctness fix; requested-root semantics remain authoritative. |
| Version identity | CLI identity was not fully tag-derived. | Inject tag/commit build metadata. | Adds truthful metadata without changing scan semantics. |
| Release modes | Preview/RC/stable procedure needed clarification. | Add release-mode procedure and evidence checklist. | Process change only. |
| Closure workflow | Owner acceptance was documented as post-merge. | Treat reviewed PR approval as owner acceptance; merge plus evidence permits `Done`. | Process clarification. |

## Accepted v0.1 limitations carried forward

- Automatic scanner installation remains unavailable.
- SBOM generation and signing remain explicit gaps until separately implemented and reviewed.
- Windows process-tree cleanup remains limited to the documented behavior.
- Remote publishing, web/history, remediation, policy baselines, SARIF, and unrelated scanner families remain out of scope.

## Compatibility review required for every change

A v0.2 issue that changes any of the following must link a compatibility decision:

- CLI command, flag, argument, or exit code.
- JSON field, schema version, serialization type, or stable key.
- Error code or failure classification.
- Scanner version range, command, exit semantics, or raw artifact format.
- Configuration file or local-data layout.
- Release artifact name, version identity, or platform matrix.

## v0.1 release dependency

The v0.2 package may be planned while v0.1 release evidence is being completed. No v0.2 implementation issue may reinterpret an unresolved v0.1 release gap as accepted without recording the owner decision and risk.
