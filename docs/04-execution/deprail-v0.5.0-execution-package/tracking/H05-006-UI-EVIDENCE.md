Platform: macOS Darwin 23.6.0 arm64; managed headless Chromium user agent Chrome/150.0.0.0. Node 22.23.3/npm 10.9.9 from the verified official Darwin archive. ## Actual surface and API scenarios

- Opened the real bootstrap URL in Chromium: `/console/` rendered 25 real history rows, newest first. The URL fragment was absent on the first rendered page; API GET paths had empty URL fragments. Local storage and session storage each contained zero entries, `document.cookie` and `document.referrer` were empty. No credential URL appeared in the rendered surface. The actual API requests were authenticated with the ephemeral in-memory bearer; no secret value is reproduced here.
- Followed history link to real detail: `cancelled` operation with `complete` report shown independently; hostile repository label `<img src=x onerror=alert(1)>` and finding component `<script>alert(1)</script>` appeared as inert text (zero `main img` and zero `main script` elements). Fixed diagnostic `CANCELLED`, provenance, workspaces and findings were visible. Diagnostic messages in the real history projection are fixed-code approved strings; this does **not** prove arbitrary hostile diagnostic text rendering through a live backend.
- A completed entry without a report displayed report/finding/workspace **unavailable**, not zero findings. Separate real entries showed `completed/failed` report with zero findings as **not a clean result**, `completed/complete` with zero as a clean empty collection, `completed/partial` with zero as incomplete, `failed/partial` with zero as incomplete, and `completed/partial` with a finding plus `SCANNER_TIMEOUT` diagnostic. A stored raw-artifact reference with no accessible raw artifact showed `Unavailable` integrity and an explicit not-verified warning.
- Real API cursor paging: page 1 and 2 each showed 25 rows; page 3 showed six and disabled Next. Previous returned to page 1. Route links and browser Back/Forward restored history/detail with headings. A canonical but absent UUID returned the actual API `HISTORY_ENTRY_NOT_FOUND` alert; the error heading received focus. Killing the running local server and choosing Refresh produced `API_CONNECTION_FAILED` with an alert/focused heading, not empty success.
- Keyboard Enter on About navigation opened `/console/about`, moved focus to the `h1` and announced `Page changed.` via a polite status region. A keyboard Tab to the footer link produced `:focus-visible` and a solid 3px blue outline. Chromium's accessibility snapshot exposed main, named navigation, headings, status, alert, list and link semantics. At a 320 CSS-pixel viewport with reduced-motion emulated, `documentElement.scrollWidth === clientWidth === 320`; navigation and detail remained visible without horizontal overflow. This viewport also approximates a 640px layout at 200% zoom; it is **not** a physical browser-zoom or VoiceOver/NVDA session.
- Reload and a new tab without a fragment displayed the focused safe-reopen heading and made no credential persistent. After reload, a same-tab `hashchange` carrying a valid bootstrap fragment removed the fragment, set a local-session status announcement and resumed authenticated API reads without storage.
- A browser request interceptor replaced one **HTTP 200 history response only** with `{ \"items\": null, \"nextCursor\": null }` to exercise the malformed-response boundary. The UI displayed `API_RESPONSE_INVALID`, not the empty-history panel. This negative injection is not represented as real-server data; normal history and detail were separately exercised against the real API after the validator change.

## PR review regression disposition

- [Stale detail-route review](https://github.com/geoffrey-xiao/deprail/pull/443#discussion_r4194384749): before fix, delayed real scan A API response changed the heading on scan B's route to A's repository. After fix, a temporary Go transport wrapper delayed the same real API response until B loaded; releasing it and waiting for network idle left scan B's heading and route intact. Detail, child collection and history reads now use request generations, invalidated on route/token changes.
- [Skip-link Back review](https://github.com/geoffrey-xiao/deprail/pull/443#discussion_r4194384757): before fix, keyboard Enter on `#main` then browser Back showed reopen/authentication-lost guidance. After fix, Back retained the active history heading and in-memory token; only an actual `token` fragment updates/revokes credentials. A hash-only `popstate` no longer cancels a pending data read.
- [Report co-presence review](https://github.com/geoffrey-xiao/deprail/pull/443#discussion_r4194384766): before fix, a synthetic HTTP 200 history row with `sourceScanID: null`, `reportStatus: complete`, `findingCount: 0`, and `sourceReportSchemaVersion: null` appeared as a clean complete zero-finding row. After fix, the same negative injection displayed `API_RESPONSE_INVALID` with zero history rows; `npm test` retains a deterministic regression for the summary and a detail/report-presence case. The normal validated real API was exercised separately.
