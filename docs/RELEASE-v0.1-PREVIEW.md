# DepRail v0.1 Preview Release

This document records the reproducible preview-release procedure and the current release gaps. It is not a production release declaration.

## Release scope

The preview includes the single Go CLI and the v0.1 flows:

```text
deprail doctor
deprail discover [path]
deprail scan [path]
```

Supported discovery boundaries are npm/pnpm/Yarn, requirements/uv/Poetry, and Maven/Gradle. Automatic scanner installation, remote publishing, remediation, policy baselines, SARIF, containers, SBOM input, licenses, secrets, and IaC remain outside scope.

## Reproducible verification

Run from a clean checkout with the pinned Go version:

```bash
make verify
git diff --check
```

The required CI matrix covers Linux, macOS, and Windows. The release gate also requires an amd64 build and an arm64 smoke run. Machine output must remain semantically equivalent across platforms.

## Artifact build and checksums

Build platform artifacts without a shell-dependent release tool:

```bash
mkdir -p dist
GOOS=linux GOARCH=amd64 go build -o dist/deprail-linux-amd64 ./cmd/deprail
GOOS=darwin GOARCH=amd64 go build -o dist/deprail-darwin-amd64 ./cmd/deprail
GOOS=darwin GOARCH=arm64 go build -o dist/deprail-darwin-arm64 ./cmd/deprail
GOOS=windows GOARCH=amd64 go build -o dist/deprail-windows-amd64.exe ./cmd/deprail
(cd dist && shasum -a 256 deprail-*) > SHA256SUMS
```

Smoke each artifact with `doctor --format json` and `discover` against the fixed mixed-repository fixture. A missing OSV-Scanner must produce an explicit diagnostic and exit code `3`; it must not produce an empty successful scan.

## SBOM and signing status

- SBOM generation: **not implemented in the repository**; release publication must not claim an SBOM until a pinned, reviewed generator is added.
- Artifact signing and provenance: **not implemented**; the v0.1 preview must record this as an explicit signing gap.
- Checksums: generated by the command above and reviewed with the artifact set.

## Automated release path

Issue `REL-002` defines the release automation path, but automatic `release-please` checks are currently paused. The workflow is manual-only through `workflow_dispatch`; it does not open or update release PRs from ordinary pushes to `main`. When intentionally invoked and merged, the tag-triggered workflow runs `make verify`, builds the four documented artifacts, generates `SHA256SUMS`, runs smoke checks, and uploads assets to the GitHub Release. SBOM generation and signing remain explicit gaps.

The artifact workflow pauses at the protected `release-approval` environment after build, checksum generation, and smoke checks. A named reviewer must approve that environment before assets are uploaded to the GitHub Release. Repository settings must configure required reviewers for this environment; the workflow reference alone does not enforce approval.

## Compatibility and known limitations

- OSV-Scanner must be installed separately and currently requires the supported v1 compatibility range.
- Discovery and scan completeness are explicit. Exit code `3` means scanner failure or incomplete scope.
- Existing output files are not overwritten by atomic presenter output.
- Windows process execution currently terminates the direct process; process-tree cleanup requires a future Job Object implementation and human review.

## Release evidence record

Before publishing, attach the commit, CI matrix links, artifact names and SHA-256 values, platform smoke output, supported scanner version, reviewer decision, remaining risks, and the owner acceptance decision to the release PR. Do not mark the Sprint or Master Checklist release items complete without those links.
